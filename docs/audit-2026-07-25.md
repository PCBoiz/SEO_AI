## 2. Secret handling

- AI keys, WordPress App Password, token FB/Zalo/GBP: mã hoá AES-256-GCM
  (Vault) với AAD riêng theo (workspace, project/user, loại) — sai ngữ cảnh
  không giải mã được. Token không bao giờ trả về browser (chỉ status/keyHint).
- Thông báo lỗi provider: cắt 200–300 ký tự + scrub pattern `sk-*`, `AIza*`
  trước khi lưu/hiển thị (`sanitize-provider-error.ts`).
- Không có `console.log` secret; logger chỉ ghi message lỗi đã scrub.
- Neon bridge vẫn dùng 2 role least-privilege; URL migrator chỉ local.

## 3. Vòng đời job

- ✅ FIXED: **Lazy sweeper** — job không kết thúc quá 15 phút (max invocation
  300s + dư địa) tự chuyển `timed_out` khi được đọc, kèm hướng dẫn chạy lại
  bằng Presets. Áp cho cả module engine lẫn Sitemap (Module 1). Không cần cron
  — hợp mô hình serverless.
- Idempotency: unique (workspace, moduleKey, idempotencyKey); payload khác với
  cùng key → 409. Race khi insert trùng đã xử lý (onConflictDoNothing + đọc lại).
- Ghim: chỉ run `succeeded` được ghim; unpin về mặc định bản mới nhất.

## 4. Validation & lỗi

- ✅ FIXED: `errorResponse` giờ map `ZodError` → 400 kèm danh sách trường lỗi
  (trước đây rơi vào 500 chung).
- Mọi input qua Zod strict; module input validate cả lúc tạo lẫn lúc engine chạy.
- Output module validate theo schema trước khi lưu.

  Đề xuất: giới hạn theo user cho POST jobs khi mở cho khách ngoài.
- **Demo/seed data** (registry Phase 2, knowledge placeholder): dọn ở Giai

  chưa có token — lần chạy đầu có thể phải chỉnh theo lỗi API trả về (message
  passthrough đã bật để thấy nguyên văn).
